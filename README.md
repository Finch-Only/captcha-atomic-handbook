# 验证码自动识别「原子能力」

一套已在两个站点落地验证的验证码自动识别能力：**手册（讲原理与经验）+ 三层代码（可直接复用）**。已验证组件：天爱 tianai-captcha 开源组件（滑块/旋转/拼接/点字四题型）+ 经典图码 OCR 链路。

| 层 | 目录 | 内容 | 换站点时 |
|---|---|---|---|
| — | `index.html` | **先读这个**：完整手册（架构图/真实时序/四类组件题型/行业通用题型/踩坑复盘/适配 checklist/参数调优器） | 只读 |
| L1 | `l1-recognition/` | 识别原子：纯图像求解 CLI，stdin→stdout 一行 JSON，**10 种题型**（通用 6 类：文本/算术/语序/点选/差分滑块/通用旋转 + 天爱特调 4 类） | **零改动** |
| L2 | `l2-page-adapter/` | 页面交互编排：弹窗→存图→调 L1→模拟鼠标→核对回执，天爱组件实测版（约 700 行） | 按组件重写一份同构文件 |
| L3 | `l3-protocol/` | 调用协议：接入方式、9 个节奏参数、失败语义、合规边界 | 参数级复用 |

## 30 秒理解三层分工

```
L3 业务采集器：翻页 → 出弹窗 → 调 L2 → 等业务载荷 → 记缺口续跑
L2 交互编排 ：等弹窗 → 存图 → spawn L1 CLI → 把答案变成鼠标操作 → 核对真实回执
L1 识别原子 ：图片进 → 坐标/距离出（模板匹配 + 几何协议 + OCR，本地推理）
```

## 快速开始

```sh
# L1 单独跑通（不碰浏览器）
cd l1-recognition
python -m venv .venv && .venv/bin/pip install -r requirements.txt
echo '{"profile":"tac","type":"slider","image":"bg.png","template":"piece.png"}' | ./run -
```

完整接入（L2+L3）见 `l2-page-adapter/README.md` 与 `l3-protocol/README.md`；适配新站点的 8 步 checklist 在 `index.html` 第 9 节。

## 核心经验（手册里有完整论证）

1. **「拖完了」≠「提交了」≠「通过了」**：判定通过必须以网络层校验回执为准，回执有迟到要按挑战 id 补捞；
2. **风控看的是频率特征**：把申请/提交离散化（分钟级换题、页间随机间隔、分批冷却）比整体放慢更有效；机器式连续重试 = 3 页即限流，模拟人工节奏 = 332 页零风控；
3. **每页一道题、一次提交**，连续失败就断点跳页 + `skippedPages` 记缺口，缺口用 `START_PAGE=N` 定点补采，绝不硬刚；
4. **`needs_human` 是能力的一部分**：识别不确定就交人工，错误放行率要在离线先测。
